## 2024-05-24 - [React Render Starvation with 60FPS Physics Loop]
**Learning:** The application features a 60FPS physics loop in `App.jsx` that frequently updates global state (`robotState`). The entire component tree was re-rendering 60 times per second, causing render starvation. Pure UI or computationally heavy child components (like SVG canvases in `WiringCanvas`) that do not depend on the fast-changing state must be wrapped in `React.memo()` to prevent unnecessary re-renders.
**Action:** When implementing heavy visual components in a physics-based simulation architecture, always separate the fast-changing state from the static UI and use `React.memo()` to isolate updates.
## 2026-08-27 - [React Render Starvation with 60FPS Physics Loop]
**Learning:** The application features a 60FPS physics loop in `App.jsx` that frequently updates global state (`robotState`). The entire component tree was re-rendering 60 times per second, causing render starvation. Pure UI or computationally heavy child components like `ArduinoEditor` and `OllamaConsole` that do not depend on the fast-changing state must be wrapped in `React.memo()` to prevent unnecessary re-renders. Furthermore, callback props passed to these components must be stabilized using `useCallback()` to maintain referential equality across renders, ensuring `React.memo()` works correctly.
**Action:** When implementing components in a high-frequency update architecture, always separate the fast-changing state from the static UI, use `React.memo()` to isolate updates, and stabilize callback props with `useCallback()`.
